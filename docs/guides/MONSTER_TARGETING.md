# 怪物索敌（本地测试）

原始规则、8张地图路线图位于工作区 `星引擎怪物索敌逻辑/`。旧算法备份位于 `XingShu-Dev/backup/checkpoint_pre_xingshu_migration/src/XingShu.Runtime/XingShuRuntime/Targeting/`；审计归档还保存了一份相同模块。

## 接入方式

- 功能中心 → 击飞预测 → **怪物索敌 · 最大10格**，提供独立开关和上/下怪物详情。开关保存在 `XINGSHU_MONSTER_TARGET_ENABLED_V1`，默认打开。
- 地图中在原击飞率/冷却行上方增加独立半透明状态行；不修改原生名字、编号、血量、引线。战斗画面不添加索敌行。
- 按用户确定的最大骰 **10格** 推演；先行1格占用步数，剩余9格用于搜索。额外步数技能暂不计入。先选择最近的目标格，再列出该格全部存活玩家：例如 `P1 + P3（同格全体）`，不将他们显示为互斥候选。
- 沿用旧模块的图搜索计算。地图邻接关系、怪物和玩家位置均从现有内存状态读取。尸体/死亡玩家不参与索敌；64位角色ID不截断。
- 首步读取 `CharacterMove` 实际绘制的可见箭头，以角色当前停留格对齐邻接出口；仅角色尚未创建时才使用经过邻接校验的 `RoomPlayer.FrontIds`。后续每一步均排除来路；按“来路格、当前格”保存搜索状态，允许真正的前行环路，禁止立即掉头抄近路。节点 `0` 是合法地图格。
- 箭头缺失、箭头不属于当前邻居或移动中箭头尚未重绘时显示“等待箭头同步”，不复用陈旧方向。已匹配的岔路按红＞蓝＞绿处理；未映射的多个出口分别计算并保留不同目标格的候选。
- 距离优先于颜色；同距目标在路径第一次真正分叉处比较红＞蓝＞绿，支持连续岔路，不用玩家座位号或对局排名决胜。同格多人共用目标格，不参与互相排除。
- 观察到当前行动怪物主动进入战斗后，本回合显示“已攻击 · 继续原路线”，不再预测追击下一格。按房间轮数及有效行动者变化清理；暂时缺失行动者时保留已攻击状态。中途加载不能恢复未观察到的历史攻击。
- 使用游戏字体、不加像素描边，使用浅黄（已确定目标格，可含多人）或浅粉（多个候选格）的半透明底衬与深色文字。标注跟随原生头顶组件缩放，索敌独立开关不依赖击飞率开关。
- 与手牌模块共用 PVE 模式判定，覆盖此前仅检查 `MapType == 10` 时漏掉的模式。各版本安装与实测状态分别记录在 `GAME_UI_R*.md`。

## 预测边界

这是最大骰点假设下的本地推演，不等同于服务器已选目标。实际骰点可能不足。

参考图已与官方客户端地块拓扑对齐，形成 8 张图、9 种场景布局、46 个岔路口的映射：星趴·梦想号、御魂庆典、水乡古镇、魔法学院外、魔法学院内（两种布局）、龙宫游乐园、幽魂暗巷、园林中庭。配置只有在完整地块连通结构及全部岔路出口吻合时启用；更新后的未知地图不会套用旧顺序。魔法学院内第二种布局的颜色对应仍待实局复核。

这些映射取自用户参考图与客户端地图资源，不等于取得了服务器端完整 AI。未覆盖的地图、无法区分的岔路仍保留候选。`RoomPlayer.Progress` 不作为路径进度，邻接数组顺序也不作为颜色顺序。

详情中的路径仅为候选最短路径示例。多个路径都可达同一玩家时，不保证与服务器实际走法一致。本次没有修改游戏AI、地图、骰子、技能或网络协议。

## 验证

`XingShu-Dev/tools/test_monster_targeting.ps1` 会重新编译当前源码，当前通过 81 项算法/预览测试和 25 项上下文测试。覆盖前后方向、先行后不掉头、环路、10/11格边界、同格2/3/4人全体、最近距离优先、同距颜色优先、连续岔路、未知岔路、死亡目标、节点0、攻击后停止、行动者临时缺失、64位ID，以及9种完整地图拓扑匹配与变化拒绝。

纯拓扑夹具保存在 `XingShu-Dev/tools/TargetingFixtures/`，附来源资源 SHA256，不包含账号和存档。提取与对照工具为 `tools/extract_target_map_graphs.py`、`tools/inspect_target_maps.py`。本轮修复与实测状态见 [同步及索敌验证记录](../records/MATCH_SYNC_TARGETING_20261024.md)。

修复依据本地游戏程序集：`UnitLand.AdjacencyLandIds` 来自 `neighborLandIds`，包含前后邻居；`CanSelectedLandId(fromLandId)` 排除来路；`CharacterMove.ShowWalkDirections(null)` 可使用当前停留格与来路重绘方向，因而不能只依赖可能滞后的 `FrontIds`。此前将邻接表整体视为有向路线的结论已纠正。
