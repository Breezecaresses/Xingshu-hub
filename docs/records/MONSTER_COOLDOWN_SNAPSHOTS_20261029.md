# 怪物数据刷新时保留 CD · r8.11 候选

## 实局证据

r8.10 在 Steam 国服本局曾正常记录：

- 玩具恐龙每次施放后 CD=1，跨轮为“预计就绪”，用户确认看到了该文字。
- 小熊在第 3 轮施放 CD=2，切换行动后仍保留 2；另一只小熊跨到第 4 轮记录了预计 1。
- 孩子王在第 3 轮施放 CD=3，切换行动后仍保留 3。

但同一局随后出现明确回退：第 4 轮 04:28:00，同一小熊实例 88302 和孩子王实例 88241 再次被记为初始 CD=0。未观察到对应的明确 CD=0 官方推送。小熊在此之前已有第 3 轮 CD=2 的施放记录，第 4 轮本应从该记录推算 1。

因此不能把上述局部正常结果当作 r8.10 实局通过；发布候选改用 r8.11。

## 修正

- 以服务器房间 ID 与开局时间标识场次，客户端 `RoomInfo`、`BattleLogic` 对象重建不再等同于换局。
- 初始快照归属集中在冷却账本中。同一怪物实例、同一角色配置与主动技能再次出现时，缺失 CD 的快照不会覆盖已有施放记录。
- 重建的 `BattlePlayerData` 可能仍来自同一个缓存 `RoomPlayer`，因此对象更换本身不能证明其 CD 映射是新回包。重复快照不覆盖施放记录；只有已解码、可归属的 CD 通知等明确来源校准。
- 临时离开棋盘显示期间仍接收可归属的技能／CD 通知，返回棋盘后继续同一场记录。
- 暂时没有房间数据、状态切换、HP/对象数据不完整和单帧缺少怪物时不清空施放历史。对不再存在于当前列表的对象释放引用，保留纯数值记录，避免持有旧游戏对象。
- 数值记录每局最多 2048 条，优先回收最久未观察的实例；真正开始新的服务器场次或宿主销毁时清理，同局战斗与棋盘切换不清理。
- 真正更换怪物配置、主动技能或服务器场次时仍隔离旧状态。跨轮推算继续标注“预计”，不冒充服务器确认。
- 不改变玩家治疗查询、怪物实际 AI、技能状态或服务器数据。

官方 `BattleLogic.BattleStart` 中包含清空 `PlayerDatas` 后重建 `BattlePlayerData` 的流程，因此不能把客户端对象引用变化本身当作服务器产生了一只新怪物。

- 玩具恐龙施放回包记录 CD=1，后续跨轮显示“预计就绪”。

- 用户已完成战斗后返回棋盘；截至该检查点，没有再次观察到上述同一怪物重复初始化为 CD=0。此结果是本次已覆盖场景的局部实测，不扩大为所有地图与怪物均实测通过。
- 第 4 轮的后台状态重新读取后为新鲜数据，与截图一致；前一条提问使用了较早的第 1 轮观察，不能据此认定当前后台仍停在第 1 轮。
