# 怪物冷却显示修复 · r8.8

本次处理采集小熊、大盗、思维飞艇空放后漏记冷却，以及小熊 2 回合冷却在下一轮直接显示就绪。只修改星枢显示与读取，不修改怪物实际技能或服务器计时。

## 官方配置

| 怪物 | 技能 | 配置冷却 |
| --- | --- | --- |
| 采集小熊 1073 | 异味蘑菇 107301 | 2 回合 |
| 大盗 1070 | 探囊妙手 107001 | 3 回合 |
| 思维飞艇 1066 | 洞悉射线 106601 | 2 回合 |

小熊、大盗的合作主动技能来自 `Monster.Attributes` 难度配置，不能只看 `Monster.Infos.ActiveSkill`。上述三种怪物各难度目前引用同一主动技能。

## 定位到的两个显示缓存问题

1. `BattleLogic.OnRoundStartS2CServerCallBack` 将同一份 `RoundStartS2C.SkillCds` 应用于所有角色；`Character.UpdateActiveSkillCD` 对未提供的技能键使用默认 0。直接读 `Property.activeSkillCD` 会把怪物缺失值当成“冷却就绪”。
2. 官方 `BattleLogic` 处理属性变化时，仅在 `account.IsSelf(_Attr.Cd.PlayerId)` 时更新本地 CD 属性。怪物的独立 CD 通知因此不一定进入该界面属性。用命中或技能动画间接判断，也会漏掉空放。

## 修复方式

- 新增显示用的独立 `MonsterCooldownLedger`，以怪物 64 位实例 ID、主动技能 ID、实际轮次保存已确认 CD，不读共享界面缓存默认值。
- 观察错误码为零的 `GetHeroInfoS2C.Cd`、属性通知中各个 `HeroCdChangeS2C`、技能使用通知。使用通知不要求 `TargetIds` 非空，也不要求播放动画或造成伤害。
- 技能使用通知未包含该技能 CD 时，撤下旧“就绪”值并安排服务器读取，不按配置最大冷却猜测当前 CD。
- 使用游戏已有的 `RequestGetHeroInfoC2S` 读取每只怪物的 CD。最多一项在途请求，间隔至少 1 秒；常规已确认数据 20 秒刷新一次，缺失数据有重试间隔。行动结束后和跨轮时优先重新核对。
- 跨轮但没有新数据时显示“冷却待同步”；明确收到当前轮的服务器 0 才显示就绪。没有本地每帧递减，也不按其他角色行动次数扣 CD。
- 旧轮次、旧技能、旧实例、旧房间的查询结果不能覆盖新数据；技能使用或独立 CD 推送会使更早请求失效。
- 所有观察方法保留官方处理流程，不写 `BattleProperty`、`Hero.SkillCds`，不改变 AI、技能或官方游戏数据。
