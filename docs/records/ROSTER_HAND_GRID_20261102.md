# 角色框旁手牌条（r8.14 → r8.17）

用户希望在棋盘左侧每个角色框旁展开手牌，同时保留原来的独立拖动手牌悬浮窗。r8.14 入口、展开与旧悬浮窗通过功能确认，之后按要求去底框、轻叠、默认 80%、去除角色旁详情。r8.16 的临时隐藏实测不完整，选目标、商店和筹码页仍会被覆盖；用户明确要求改为原生头像组件层级。r8.17 将角色旁手牌绘制迁回 FairyGUI 原生层级，不再创建独立 Unity Canvas。自由镜头 r8.13 的已确认修复保留。

## 最终行为

- 角色框右侧显示“手牌”按钮，默认折叠；四位玩家分别展开或收起。
- 位置跟随原生角色框及排名变化，展开状态按玩家身份保存。切入战斗再回棋盘保留，同房间重开一局则清空旧状态。
- 单张卡牌直接横向排列，包含卡图、名称和费用；没有整条白色底框、页码或翻页按钮。牌多时最多重叠 28%，超出可左右拖动或滚轮横向查看。
- 角色旁卡牌默认缩为原来的 80%，可在 60%–150% 内调节；旧的接近 100% 默认值一次迁移到 80%，其他自定义值保留。
- 角色旁卡牌没有悬停和点击详情逻辑，只显示卡图、名称与费用。原独立手牌悬浮窗继续单独使用。
- 布局按照角色行距和安全区约束为一排；每个角色行单独拦截点击，行间空白仍可操作游戏。原生面板切入战斗时缩小到接近零会隐藏入口，避免闪到屏幕原点。
- “手牌监视”增加角色旁入口开关、卡牌大小（60%–150%）；原独立悬浮窗按钮与大小调节保留。
- 角色旁手牌组件直接 `AddChild` 到原生 `UIBattleInfo_Button_PlayerInfo`，随头像移动、缩放、遮挡及销毁。通过屏幕到父组件坐标变换保留已确认的大小和偏移。
- 从 `GRoot` 读取实际显示的原生交互窗口，避开未填充或过期的 `UIManager` 缓存。选择目标、商店、筹码、战斗等交互窗口显示时，角色旁入口和卡牌与原独立悬浮窗暂时隐藏，关闭后恢复原有展开及横向位置。不通过查询创建窗口。
- 共用既有手牌同步及原画资源选择。未同步或被遮蔽的数据显示真实缺失状态，不增加手牌请求方式。

## 实现范围

`HandCardRoster.cs` 使用 `GComponent`、`GImage`、`GTextField` 绘制，原生触摸和滚轮事件驱动横向拖动，卡牌本身无点击或悬停详情。`HandRosterLayout.cs` 计算边界和轻叠，按玩家保存展开与横向位置。通过现有 `HandCardDisplayManager.Install` 挂载，原 `HandCardDock` 保留。`HandCardVisibility.cs` 遍历实际原生窗口，两个视图共用临时隐藏条件。

对照了本机最初 `baseline/dlls/APX.hooks.dll`：其 `AttachOrUpdateWidget` 将手牌组件 `AddChild` 到 `UIBattleInfo_Button_PlayerInfo`，使用原生 UI 层级。未在手牌管理器中发现直接调用筹码选择状态。r8.17 采用该父子层级关系，并补充实际交互窗口门控；原生遮挡和显式隐藏分别保留。

手牌内容按现实时间每 0.25 秒采样，卡图仅在内容或布局变化时重建；横向拖动仅移动已有卡牌，不反复加载卡图。原生框位置每帧跟随。异步卡图加载有代次检查，离开对局或换玩家后不会写回旧图。
