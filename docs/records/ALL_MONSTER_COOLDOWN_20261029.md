# 全怪物冷却排查 · r8.9 候选

**后续实测未通过。** r8.9 切换行动时清空了已确认的 CD，而且本局 NPC 查询没有匹配的有效回包。修正方式与仍待验证的边界见 [r8.10 事件跟踪记录](MONSTER_COOLDOWN_EVENTS_20261029.md)。本页保留当时的候选设计和离线检查结果，不作为实局验收结论。

## 范围与配置

这次覆盖本地官方 3.3.0 / 资源 026 的全部 84 条怪物记录，不再仅限采集小熊、大盗和思维飞艇。配置原文件不修改。

- 56 条记录至少在一种模式或难度下具有主动技能；28 条没有配置主动技能，不显示主动技能 CD。
- 共 50 个不同主动技能，258 个有主动技能的默认／合作难度分支；配置冷却包含 1、2、3、4、99。
- 8 条记录会随合作难度更换技能或从无主动技能变为有：1011、1013、1030、1038、1043、1045、1049、3051。
- `MonsterInfoConfigure.GetBattleActiveSkillId()` 在合作模式查找匹配难度的 `PveActiveSkill`，包括合法的 0；只有没有匹配分支时才回退 `ActiveSkill`。不能把低难度的无技能错误回退成默认技能。
- 运行时沿用官方 `RoomPlayer.GetBattleActiveSkillId()`，不维护小熊等怪物白名单，也不使用技能配置最大 CD 代替当前实例剩余 CD。

全量审计工具：`tools/audit_monster_cooldowns.py`。本机证据：`XingShu-Dev/build/monster-cooldown-20261028/all-monster-audit/all-monster-cooldowns.json`、同目录完整表和 `cooldown-variants.csv`。配置 SHA256 为 `674e027707b5a5890487008d1014efae11b03242213ca67d064ddad46d4c00da`，缺失技能引用与重复难度检查均为零。

## 公共逻辑修正

1. r8.8 已停止读取共享回合 CD 映射缺失键的默认 0，改为每个怪物实例独立保存明确回包。空目标使用通知同样处理。
2. r8.9 移除同步器仅限合作模式的条件，其他对局中具有主动技能的怪物也纳入；仍要求有效战斗场景、运行中的房间、存活怪物及有效主动技能。
3. 显示开关不再清空冷却账本；关闭或重开击飞概率窗口不能使已观察的技能使用消失。
4. 刷新、超时与节流改用 `ThinkingClock.RealSeconds()` 的单调累计时间，避开桌面原生加速影响 Unity 计时的问题。
5. 增加限量日志，区分同步器是否运行、服务器错误、超时、未匹配到解码回包、接收或拒绝过期回包。日志只含怪物实例、技能、轮次和状态，不记录登录信息。
6. 多段技能的使用 ID 不同于配置主动技能时，仍接收该怪物回包中明确提供的主动技能 CD；没有对应值的无关被动不会触发主动 CD。场次隔离同时核对房间 ID 和开局时间。

跨轮但未拿到当前轮确认值仍显示“冷却待同步”。只有服务器明确返回 0 才能建立就绪状态；不会因为没有动画、没有目标、暂时没有通知或共享表没有键就补 0。

## 已做与待验

- 配置审计覆盖全部 84 条怪物记录，258 个有效主动技能分支；零异常引用。
- 4 项配置边界回归通过：显式无技能、缺失技能定义、合法零冷却、重复难度。
- 冷却账本 2615 项检查通过，包含每个有效分支的空放失效、同技能不同实例隔离、跨轮延迟、死亡移除、99 回合值保留，以及多段技能与无关被动区分。
- r8.8 本机实局记录了 27 条技能使用通知，技能为 107101、107201、107301；技能使用时正数冷却有记录。
- 该局没有确认到独立 `GetHeroInfo` CD 或属性 CD 日志，因此跨轮同步仍为未验证，不能宣称全怪物实局通过。`TargetIds.Count == 0` 本身也不足以判定实际空放。
- r8.9 的构建、四渠道观察点校验及后续实局结果写入本机构建收据，不以离线回归替代逐局验收。
