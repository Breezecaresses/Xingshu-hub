**后续实测发现刷新重置问题，r8.10 不发布。** 施放保留和跨轮推算在局部记录中生效，但同一只怪物刷新数据后仍被初始化为 0。后续 r8.11 修复与验证边界见 [数据快照刷新修复记录](MONSTER_COOLDOWN_SNAPSHOTS_20261029.md)。

## r8.9 实测暴露的问题

用户在 Steam 国服合作人机局观察到：怪物初始可用技能却显示“冷却待同步”；技能使用之后也再次回到同一提示。小熊、孩子王和玩具恐龙均受影响。

本机保留的该局日志有 7 条技能使用通知、19 条“没有匹配的解码回包”状态记录、0 条已确认的独立 CD 查询记录。次数是日志记录次数，不代表请求总数或完整覆盖所有怪物。由此只能确认该局的查询路线没有提供可归属的怪物 CD，不能推断所有模式的接口永久不可用。

代码中的直接错误是：`ObserveAction` 在切换到下一个行动角色时对上一只怪物执行 `Invalidate`。它会清空刚从技能通知确认的 CD，而查询没有有效回包，造成长期“待同步”。此前离线测试未覆盖这个真实控制流程。

## r8.10 的行为

- 移除星枢主动发出的 NPC `GetHeroInfo` 轮询；玩家治疗统计所使用的请求不改动。
- 行动切换保留 CD，不因为其他角色移动、使用技能或切换行动清空或递减。
- 每只怪物首次出现时读取其独立 `Hero.SkillCds`。官方 `Character.InitSkill` 也从此处初始化；缺少主动技能键时的初始 0 只作为**预计就绪**，不冒充明确回包。只初始化一次，不能覆盖先到的技能使用通知。
- 技能使用通知明确给出主动技能 CD 时直接保存，包括 `TargetIds` 为空的通知；不要求动画或伤害。通知缺少 CD 时，可用该技能配置的冷却建立**预计冷却**，有冷却修正效果时可能与实际值有差异。
- 根据已观察的真实轮次跨轮推算。例如第 3 轮确认 CD=2，第 4 轮显示“预计冷却 1 回合”，第 5 轮显示“预计就绪”。同轮四个玩家依次行动不算四轮，重复轮次通知不重复扣减。
- 回合消息的 CD 映射由 `RoundStartS2C.PlayerId` 归属，只接收明确属于这只怪物且包含当前主动技能键的值。其他玩家的映射和缺失键不作为怪物 0。
- 收到可归属的官方 CD 推送／详情回包时立即校准为明确值。新回包可能修正之前的预计值。
- 真正没有记录时显示“冷却未记录”，不再承诺存在一个正在等待的查询。
- 房间、开局时间、怪物实例或技能变化保持隔离；仅读取游戏信息和修改星枢显示，不改变怪物实际 AI 或技能。

跨轮递减是根据施放记录和标准轮次规则的推算，**不是本局已经验证的服务器剩余 CD**。特殊减冷却、重置或未观察到的施放会造成偏差，因此预计值始终标注“预计”，不得以此宣称全怪物实局验证通过。
